# MentalSim JS

**JsPsych implementation of the MentalSim navigation experiment**

A web-based psychological experiment using [JsPsych](https://www.jspsych.org/) that implements the MentalSim paradigm for studying human navigation performance. This is a browser-based version originally developed for MEG (Magnetoencephalography) studies.

## What the Code Achieves

Going through the code shows that this project turns the original MentalSim navigation task into a browser-run jsPsych experiment with a complete participant flow, configurable trial loading, stimulus rendering, response capture, feedback, and data saving.

At a high level, the implementation achieves the following:

- Builds a participant-ready web experiment from modular jsPsych trial plugins.
- Uses admin-generated URLs so each participant receives a locked configuration for subject, session, sequence, run count, cohort, participant UUID, and session ID.
-
- 
- Loads trial schedules from cohort-specific CSV files in `public/input/<cohort>/subj-XX/ses-XX/input.csv`.
- Loads category-sequence metadata from `public/input/<cohort>/category_sequences.csv` and maps sequence positions into the experiment's stimulus categories.
- Presents a mandatory consent step before the task begins.
- Preloads the relevant stimulus images before the timeline starts.
- Runs each selected trial through the MentalSim sequence: optional speed cue, blink fixation, sample display, movement response, feedback, and inter-trial interval.
- Captures timing, frame-level movement state, response release timing, target distance, feedback metrics, and jsPsych trial data.
- Saves the finished dataset as both JSON and CSV through `/api/save`, using Vercel Blob when configured or `/tmp/navigate-data` as a local fallback.

## Code Walkthrough

The main entry point is `src/experiment.js`. It performs most of the orchestration:

1. `setupInitialValues()` reads experiment configuration from the URL, preferring the encoded `cfg` parameter generated by the admin page.
2. `/admin` renders a token-protected form that generates participant URLs with a stable `participantUuid` and `sessionId`.
3. The participant page requires a valid `cfg`; without one, it displays a message asking the participant to request an admin link.
4. `configureParams()` loads the category sequence CSV and updates shared `params` values such as subject, session, sequence, cohort, category order, and navigation direction.
5. `loadTrials()` loads the subject/session trial CSV and filters out probe rows by keeping rows where `is_probe === 0`.
6. `preloadStimulusImages(params)` prepares the image assets needed by the configured category order.
7. The jsPsych timeline is built run by run from the selected CSV rows.
8. `on_finish()` posts the complete jsPsych dataset to `/api/save`.

The experiment parameters live in `src/params.js`. This file defines the display geometry, colors, visual-angle conversion, stimulus paths, audio cue settings, default cohort and participant metadata, and helper functions such as `degToPx()` and `layoutParams()`.

CSV parsing is handled by `src/csv.js`. The parser supports quoted fields and converts numeric-looking cells into numbers, which lets the trial plugins use values such as `speed`, `run`, `sample_dur`, and `feedback_dur` directly.

Stimulus drawing and preloading are handled in `src/stimuli.js`. Trial plugins call `drawStimulusImage()` to render category images onto a canvas using the configured category order and image size.

## Trial Flow

Each trial row becomes a sequence of jsPsych plugin trials:

- `NavigateSpeedCuePlugin` (`src/trials/speed-cue.js`) runs when `speed_cue_dur > 0`. It displays FAST/SLOW and LIGHT/DARK cue text, animates the stimulus stream at the trial speed, and records frame-rate diagnostics.
- `NavigateBlinkFixationPlugin` (`src/trials/blink-fixation.js`) presents the blink/fixation phase using the configured fixation timing.
- `NavigateSamplePlugin` (`src/trials/sample.js`) shows the current sequence state and the target item. The participant can release the M key to end the sample early, or the sample ends after `sample_dur`.
- `NavigateMovementPlugin` (`src/trials/movement.js`) animates the stimulus sequence during the navigation response. It tracks M-key release time, elapsed movement duration, sequence shifts, final positions, target distance, and optional alpha-synced tones.
- `NavigateFeedbackPlugin` (`src/trials/feedback.js`) reads the previous movement trial, computes how far the selected/current item is from the target, and displays graded feedback.
- `NavigateItiPlugin` (`src/trials/iti.js`) presents the inter-trial interval.
- `NavigateBreakScreenPlugin` (`src/trials/break-screen.js`) appears between runs when more than one run is selected.

## Data Output

At the end of the experiment, `saveExperimentData()` sends a payload containing:

- save timestamp
- experiment name
- participant UUID and session ID
- subject, session, sequence, and cohort
- selected run numbers
- all jsPsych rows as structured JSON
- all jsPsych rows serialized as CSV

The API route in `api/save.js` stores the data under a path organized by cohort, subject, session, and session timestamp. If `MENTLASIMJS_BLOB_STORE_ID` is present, files are uploaded to the connected private Vercel Blob store. Otherwise, local development saves files into `/tmp/navigate-data`.

## Features

- **Browser-based navigation experiment** with keyboard and pointer responses
- **Multiple trial types**: speed cues, blink-fixation, sample, movement, feedback, and ITI (inter-trial interval)
- **Flexible configuration** via URL parameters or admin interface
- **Automatic data collection** and saving to backend API
- **Responsive design** optimized for desktop experiments
- **Audio support** with configurable sound cues
- **Cohort-based trials** organized by directory
- **Informed consent screen** with automatic consent ID generation

## Consent Screen

The experiment includes a mandatory informed consent screen that participants must complete before beginning.

- **Consent ID**: Automatically generated unique identifier (format: `CS-[TIMESTAMP]`)
- **Consent Date**: Timestamp of consent
- **Complete Information**: Covers all IRB-required elements
- **Data Collection**: Consent information saved with experiment data

Participants will be shown a comprehensive consent form covering:
- Introduction and purpose
- Procedures and duration
- Risks and benefits
- Confidentiality protections
- Voluntary participation and withdrawal rights
- Contact information
- Research participant rights

The consent screen appears at the beginning of the experiment flow, before the setup screen. Participants can press M to toggle the agreement checkbox, then press ENTER or click the start button to continue.

To customize the consent form, edit `src/trials/consent.js` and replace bracketed text with your specific information.

For more details, see `public/CONSENT_GUIDE.md`.

## Usage

### Participant Flow

1. **Consent Screen**: Read and acknowledge the informed consent form
2. **Setup screen**: Enter subject ID, session number, sequence ID, maximum runs, and cohort directory
3. **Trial sequence**: Speed cue → Blink-fixation → Sample (display target) → Movement (hold key) → Feedback → ITI
4. **Data collection**: Data is automatically saved to the backend API upon completion

### Trial Types

- **Speed Cue**: Brief visual or auditory cue indicating target direction
- **Blink-Fixation**: Pulsing fixation cross with random timing
- **Sample**: Displays the target location for a limited time
- **Movement**: Participant holds down a key while navigating
- **Feedback**: Immediate visual feedback about response accuracy
- **ITI**: Brief inter-trial interval with fixation

## Configuration

### URL Parameters

The experiment supports configuration via URL query parameters:

- `cfg`: Encoded configuration (preferred method)
- `subid`: Subject ID
- `session`: Session number
- `seqid`: Sequence ID
- `runs`: Maximum number of runs
- `dev`: Dev mode (set to `1` for limited trials)
- `cohort`: Cohort directory name
- `n`: Limit number of trials

### Configuration Parameters

Edit `src/params.js` to customize:

- **Visual parameters**: Screen dimensions, viewing distance, colors
- **Trial timing**: Fixation durations, trial intervals, feedback duration
- **Stimuli**: Category list, number of images per category, stimulus path
- **Audio**: Enable/disable sounds, frequency, volume, duration
- **Navigation**: Target direction, inter-limb distance, response key

Key parameters:
- `screenWidthPx`, `screenHeightPx`: Display dimensions in pixels
- `viewingDistCm`: Distance from participant to screen
- `targetYDeg`: Vertical target position in degrees
- `ildDeg`: Inter-limb distance (between visual targets)
- `fixColor`: Fixation cross color
- `cohortDir`: Directory containing trial CSV files

## Admin Interface

Access the admin interface at `/admin` to:

- Generate participant URLs with encoded configurations

## Data Structure

The experiment collects response timing, accuracy, and other behavioral metrics:

- Response times
- Key presses
- Trial outcomes (correct/incorrect)
- Navigation performance metrics
- Consent ID and consent date

Data is saved in CSV format to the backend API endpoint `/api/save`.
